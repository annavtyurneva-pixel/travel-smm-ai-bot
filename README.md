# Travel SMM AI Assistant

Telegram-бот для подготовки и подтверждённой публикации контента тревел-канала. Это учебный MVP итогового проекта по промпт-инжинирингу.

Репозиторий проекта: <https://github.com/annavtyurneva-pixel/travel-smm-ai-bot>

## Проблема и идея

Администратору тревел-канала приходится отдельно искать темы, писать текст, готовить иллюстрацию и переносить материал в Telegram. Бот объединяет эти операции в один управляемый сценарий, но не публикует материал без явного подтверждения человека.

## Возможности MVP

- пять идей публикаций;
- последовательный сбор брифа: направление, аудитория, формат, тон, цель и тема;
- генерация русскоязычного поста;
- отдельный визуальный промпт и генерация иллюстрации;
- предпросмотр текста и изображения;
- независимая перегенерация текста или изображения;
- сохранение одного текущего черновика администратора в SQLite;
- дополнительное подтверждение перед публикацией;
- публикация только в разрешённый канал;
- безопасная обработка длинного текста;
- автономный мок-режим без платных API.

## Стек и архитектура

- Python 3.11+;
- aiogram 3.x и FSM;
- OpenAI Responses API и Images API;
- SQLite через aiosqlite;
- python-dotenv;
- pytest и pytest-asyncio.

```text
Telegram handlers/FSM
        │
        ├── LLMService ───── Mock или OpenAI
        ├── ImageService ─── Mock или OpenAI
        ├── DraftStorage ─── SQLite
        └── Publisher ────── Telegram-канал
```

Telegram-обработчики не зависят от конкретного AI-провайдера: реализации выбираются при запуске.

## Пользовательский сценарий

```text
/start → идея или создание поста → бриф → текст → изображение
       → предпросмотр → изменения → запрос публикации
       → повторное подтверждение → заданный канал
```

## Установка на Windows в VS Code

Откройте PowerShell в каталоге проекта:

```powershell
cd C:\Users\АННА\Desktop\Agent007\travel-smm-ai-bot
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Ожидаемый результат: появятся локальные `.venv` и `.env`. Они исключены из Git.

Если PowerShell запрещает активацию, окружение можно не активировать и вызывать Python явно:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_tests.ps1
```

## Настройка `.env`

```dotenv
MOCK_MODE=true
TELEGRAM_BOT_TOKEN=
ADMIN_TELEGRAM_ID=ваш_числовой_id
TARGET_CHANNEL_ID=-100xxxxxxxxxx
OPENAI_API_KEY=
OPENAI_TEXT_MODEL=gpt-4.1-mini
OPENAI_IMAGE_MODEL=gpt-image-1
DATABASE_PATH=data/travel_smm.db
LOG_LEVEL=INFO
```

Никогда не отправляйте ключи в чат и не добавляйте `.env` в Git.

## Тестовый режим без расходов

Установите `MOCK_MODE=true`. Бот выдаёт предсказуемые идеи и пост, а также создаёт локальную PNG-заглушку 512×512. Для работы самого Telegram-интерфейса всё равно нужен токен созданного бота, ID администратора и ID тестового канала. OpenAI-ключ не нужен.

## Запуск

```powershell
.venv\Scripts\python.exe -m app.bot
```

Ожидаемый результат: в терминале появится сообщение о запуске. Откройте бота в Telegram и выполните `/start`. Остановить процесс: `Ctrl+C`.

## Автоматические тесты

```powershell
powershell -ExecutionPolicy Bypass -File .\run_tests.ps1
```

Зафиксированный результат на 7 августа 2026 года: `34 passed`. Тесты замоканы и не отправляют сообщения, не публикуют посты и не расходуют API-кредиты.

## Подключение к каналу

1. Создайте бота через официальный `@BotFather`.
2. Создайте отдельный тестовый канал.
3. Добавьте бота администратором канала с правом публикации.
4. Получите числовой ID канала (обычно начинается с `-100`).
5. Заполните три Telegram-переменные в `.env`.
6. Сначала оставьте `MOCK_MODE=true` и выполните ручной сценарий.
7. После успешной проверки добавьте OpenAI-ключ и установите `MOCK_MODE=false`.

Подробнее: [docs/telegram_setup.md](docs/telegram_setup.md).

## Меры безопасности

- доступ только для `ADMIN_TELEGRAM_ID`;
- публикация только в `TARGET_CHANNEL_ID`;
- обязательное повторное подтверждение;
- секреты только в исключённом `.env`;
- внешние ошибки преобразуются в безопасные сообщения;
- полные ответы API и токены не логируются;
- изменчивые сведения предлагается перепроверять по официальным источникам.

## Ограничения и известные особенности

- поддерживается один администратор и один текущий черновик;
- нет расписания, аналитики, CRM, платежей и веб-панели;
- реальные Telegram/OpenAI интеграции требуют ручной проверки владельцем аккаунтов;
- бот использует long polling, поэтому процесс должен оставаться запущенным;
- OpenAI доступность, модели и стоимость зависят от аккаунта провайдера;
- сгенерированный материал необходимо проверить перед подтверждением.
